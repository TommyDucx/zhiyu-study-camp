01 / EVIDENCE

图谱先说实话。

工作区是一个内容生产仓库，不是单一应用仓库：HTML、Python 构建器、试题 PDF 和生成物混在一起。图谱显示 HTML 节点形成多个巨大社区，调用解析率低，测试覆盖近乎为零；它适合发现热点，不适合把整座仓库当作一个可发布项目。

为什么不在原目录直接开源

为什么复习资料不进仓库
完整 HTML 留在本机，应用只通过目录权限读取。公开仓库携带源码、测试、角色素材和文档；个人笔记仍然可以完整使用。
重构后的新图谱： 19 个源文件、287 个节点、2,095 条边、23 个 Test 节点、无 import cycle。剩余高连接热点集中在 bindEvents、openDocument 与 renderAll，这正是下一步浏览器烟测应覆盖的区域；学习规则已经退到可测试的引擎 seam 后面。

03 / CURRENT SHAPE

现在的运行结构。

领域规则与 DOM 解耦，存储退到适配器后面，发布物由构建器统一生成。账号仍在本机，容量和同步边界被明确写出，不假装它是服务端系统。

flowchart LR
  DATA["游戏目录<br/>学科 · 成就 · 奖励"] --> ENGINE["学习引擎<br/>通读 / 打卡 / 宝箱 / 兑换"]
  SOURCE["本机复习文件<br/>File System adapter"] --> LIBRARY["分层索引<br/>99 docs / 50 folders"]
  LIBRARY --> APP["阅读器与营地 UI<br/>滚动完成 · 账号 · 反馈"]
  ENGINE --> APP
  STORE["进度仓储<br/>Web Storage adapter"] <--> APP
  ENGINE --> TEST["Node 规则测试<br/>23 passing"]
  APP --> BUILD["单文件构建<br/>inline + verify"]
  BUILD --> DIST["dist/index.html<br/>offline shell"]
接口纪律： `app.js` 不知道 `awarded` 账本，`engine.js` 不知道 `document`，`storage.js` 不知道奖励规则。每一个位置只保留自己的复杂度。
04 / NEXT

还留着一处诚实的技术债。

UI 渲染仍然集中在一个 103 行、长模板密集的模块里。它不是本轮最危险的地方，因为规则已经移出；但下一次出现大量页面改动时，应按页面拆成独立 render 模块，并增加浏览器烟测。

WORTH EXPLORING

下一步：浏览器烟测层

目前的 23 条测试穿过学习引擎、目录索引与仓储适配器，也覆盖了真实目录规则；但按钮绑定与自动滚动完成仍需浏览器验证。下一步应把已执行的浏览器烟测固化为 CI 任务。

  • 01 Playwright smoke: 导入 → 展开 → 打开全文 → 滚到底
  • 02 注册、登录、错误密码、刷新恢复
  • 03 390px 视口无横向溢出且进度条不被导航遮挡
  • 04 产物 dist 与源站行为一致

不急于做的两件事

不要立刻引入前端框架。当前模块只有一个页面与一条状态流；引入框架只会增加构建与依赖成本。

不要把 local-first 改造成账号服务器。在出现跨设备同步或排行榜之前，本机账号是正确范围；引入服务端后必须重新设计安全与反作弊。

Top recommendation: 先补浏览器烟测，再根据真实改动压力拆 UI。保持规则模块稳定，避免为了文件夹结构而再搬一次家。
